# 11. 백업, 복원 및 기타 기능 들

## 1. 백업
- 백업/복구는 실제 테이블 읽기-쓰기와는 독립적으로 작동
- DDB에서 로그 아카이빙 에이전트가 각 스토리지 노드에서 wrtie-aheads-log, 쓰기전 로그(테이블에 수행된 모든 쓰기 작업 기록)를 S3에 로드
  - 3개의 에이전트 중 하나가 로그 아카이빙 나머지 2개는 데이터 유효성 검사 진행
- DDB는 파티션 데이터들도 사용함

### 1-1) 온디맨드 백업
- 사용자가 필요할 때 백업 생성가능, 오래 보관해야 하는 백업에 잘 맞음
- 테이블에 대한 모든 정보 : 테이블 스키마, 용량 설정, 인덱스 정보, 백업 메타 데이터(고유 id, 시각, 태그)

### 1-2) 온디맨드 백업이 맞지 않는 경우 : 특정 사용자 데이터 개발 삭제
- 지역 데이터 개인 정보 보호 규정에 따라 개별 사용자 기록 삭제가 필요하면 온디맨드 백업을 사용하지 않는 것이 좋음
- 한건이라도 백업에서 지우려면 : 1. 백업 전체를 새 테이블 복원 -> 2. 레코드 삭제 -> 3. 복원 테이블을 다시 백업 


###  1-3-1) 관리 방법 : DDB 자체 관리
- 백업은 테이블과 같은 계정에 백업 관리 가능
- 사이즈와 무관하게 즉각적인 백업본 생성 가능 - 백업할 때 테이블 데이터를 실제로 읽지 않기 때문 
  - 주기적 snapshot + write-ahead logs로 애플리케이션에 거의 영향 안주는 백업본 생성 가능

### 1-3-2) 관리 방법: AWS Backup
- 활성화 방법 : DDB 콘솔 백업 페이지 -> Aws Backup 고급기능을 킴
  - 기존 백업은 DDB가 관리 -> 새로 만드는 백업부터 Backup이 관리하고 과금
- 추가로 쓸 수 있는 기능
  - 교차 계정 복사 : 원본이 대상 계정과 같은 AWS Organizations에 속해있어야 함
  - 교차 리전 복사
  - 콜드 스토리지 전환 : 일정 기간이 지나면 더 저렴한 저장소로 옮김
  - 백업 볼트와 백업 플랜 : 여러 AWS 서비스 백업을 한곳에서 관리하고 보존 기간 및 오래된 백업 자동 삭제 지원

**[DDB 자체 관리 vs AWS Backup 비교표]**

| 항목 | DynamoDB 자체 관리 | AWS Backup 관리 |
|---|---|---|
| 저장 위치 | 같은 계정, 같은 리전 | 교차 계정·교차 리전 복사 가능 |
| 생성 속도 | 즉시 (크기 무관) | 즉시 (같은 내부 구조 사용) |
| 보존·교체 자동화 | 자동화는 없고 매번 API 호출 | 백업 플랜으로 자동화 |
| 콜드 스토리지 | 지원 안 함 | 지원 - 웜은 저장 비쌈 + 복구 저렴, 콜드는 저장 저렴 + 복구 비쌈 |
| 과금 | DynamoDB 요금 | AWS Backup 요금 |

### 연속 백업(PITR) - Point in time recovery
- 테이블 데이터를 계속 자동을 백업 -> 35일 내 어느시점으로든 초 단위로 복원가능
- 복원 가능한 이른 시점은 min(35일 전, PITR을 마지막으로 켠 시점) 중 최근 시점
- ex) 테스트 앱이 실수로 운영 테이블의 데이터 손상 -> PITR 사용하면 손상 시점 이전으로 돌릴 수 있음
  - 복원 결과는 새 테이블로 생성됨
  - 새 테이블을 참고해 원본 테이블의 손상 데이터를 바로잡을 수 있음

**[실수로 삭제했을 때의 보호]**
- PITR : PITR 켜진 테이블이 삭제 되면 -> DDB가 삭제 직전 상태로 백업 만듦
- 삭제 방지 : 이 설정을 먼저 꺼야만 테이블을 삭제 가능(콘솔 체크박스나 API로 설정 가능)
-> 운영 테이블을 삭제한 고객들에 대해서 PITR을 켜 둔 고객은 빠르게 복구했지만 삭제 방지와 PITR을 모두 설정하지 않은 고객은 데이터를 되살리지 못했음

**[PITR 동작원리]**
- Write-Ahead Log + 주기적 스냅샷 -> S3에 아카이브 됨
  - WAL에 있는 타임 스탬프 기준으로 복구 시점 이전의 로그만 적용함
  - 백업/복원 중에 테이블 성능에 영향 없음 -> 운영 테이블에는 켜두는 것 권장

**[백업과 복원의 보안]**
- 암호화
  - DDB 백업은 DDDB 테이블에 연결된 KMS키로 자동 암호화됨
  - Aws Backup으로 관리한다면 테이블고 다른 KMS 키 지정 가능
- IAM으로 관리방식에 따라 DDB 요청에 대한 권한 제한 가능
- Aws Backup : Vault Lock(한 번 넣은 백업은 정해진 기간이 끝나기 전까지 누구도 지우거나 고칠 수 없게 잠그는 기능") -> 볼트에 들어간 백업을 누구도 삭제 못하게 가능

- 운영테이블에는 PITR + 삭제 방지를 둘다 켜는 것이 기본
- PITR은 35일 초 단위 복원을 지원하고 복원은 항상 새 테이블로 이루어짐
- 보안은 KMS 암호화, IAM Deny 정책, 필요하면 Valut Lock으로 강화 가능

### DDB 복원
- 온디맨드 백업 : 백업 생성 시점
- PITR : 사용자가 지정한 복원 대상 시점
- 어떤 방식이든 복원은 항상 새 테이블로 생성되기 때문에 원 본 테이블을 변경하지 않음

### 복원 시 복원 대상에서 복사되는 것과 새로 초기화되는 것
- 백업에서 복사되는 것 : 과금 모드 + 읽기/쓰기 용량 + 암호화 설정
- 복사 안되어 새로 설정해주어야 하는 것 : 오토 스케일링 , TTL, 리소스 태그, 스트림 설정 등

### S3 Export
- DDB Json, Amazon Ion
- 같은 region, account가 아니더라도 export 위치로 지정 가능
- PITR이 반드시 켜져 있어야 함 -> 내보내기도 아카이브된 WAL과 스냅샷을 사용하기 떄문에
- 백그라운드에서 비동기로 처리되므로 테이블 성능에 큰 영향이 업승ㅁ

### 두가지 방식 Export
- Full Export: 전체 덤프
- Incremental export : 시작-종료 시각을 지정하면 바뀐 델타만 내보냄
-> 주기적으로 전체 내보내기 or 전체 1회 + 증분 반복

### Export성능과 비용 요약

**[성능]**
- 출력 데이터 파일 하나에 압축전 기준 약 1GB가 담김
- 파일은 GZIP으로 4:1 압축됨
- 테이블이 수백 GB 미만이면 테스트상 대부분 30분 안에 끝남

**[비용 구성]**
- DDB 내보내기 요금 : 테이블 크기 GB당 과금
- S3 PUT 요금 : 64MB 당 PUT 1회
- 다른 리전 버킷으로 내보내면 리전 간 데이터 전송 비용 추가

**예시)**

| 항목 | 계산 | 결과 |
|---|---|---|
| S3 객체 수 | 20GB ÷ 1GB | 20개 |
| S3 저장 크기 | 20GB ÷ 4 | 약 5GB |
| PUT 횟수 | 5GB ÷ 64MB | 약 80회 |
| DynamoDB 요금 | $0.11886 × 20 | 약 $2.37 |
| S3 PUT 요금 | $0.0053 / 1000건 × 80 | 약 $0.0004 (책에는 $0.42로 표기) |
| **총합** | | **약 $2.37** (책에는 $2.79로 표기) |

**[한계]**
- 원시 형식: DDB Json/Ion 형식이라 데이터 분석을 위해선 추가 가공 필요
- 실시간 아님 : 수동 실행에 따른 배치 처리이므로 실시간 동기화는 아님
- 변환/정제 기능 없어서 AWS Glue로 변환하거나 일부 데이터만 덤프 요청해야함

## S3 Import
- 대량 데이터 적재, 야간 대량 로딩, 다른 DB 클라우드에서 마이그레이션, 새 테이블 초기 데이터 채우기 등등
- 지원 형식 : CSV, DynamoDB JSON, Amazon Ion, 압축 파일(GZIP)
- 보조 인덱스 : 가져오고 동시에 만들 수 있지만 인덱스 import 후 gsi 추가가 더 빠름
- 인덱스 비용 : 가져오기 중에 생성되는 인덱스는 채우는 비용이 무료임
- 항목 크기 : 200Byte 미만의 작은 항목이 많으면 오래걸림
**- 데이터 순서 : 파일 간 무작위로 섞인 데이터가 빠르게 적재됨 -> 파티션 쓰기가 고르게 분산되기 때문**
- 요금 : S3 소스 데이터 압축 해제 기준 GB 당 정액으로 부과

**[한계]**
- 새 테이블로만 가져올 수 있음 : 기존 테이블에 넣는 Import는 안됨
- CSV는 타입 정보가 사라지고 모든 속성이 String으로 들어감
- 대안 : AWS Glue 기반 서버리스 파이프라인
